Decision

A separate shutdown-only terminal-outcome reconciliation path is structurally viable and preferable to broadening no-effect recovery. It can truthfully retire a failed/canceled attempt while preserving possible writes and refusing publication. It is not yet qualified by the available durable evidence. The missing decision is what process coverage justifies processQuiescent: a provider-managed background-terminal cleanup receipt, independently observed process-group absence, or another explicit trusted process proof. A thread cleanup acknowledgement must never silently become proof of arbitrary escaped processes being gone.

Smallest safe contract for implementation

1. Limit the new path to fenced shutdown with no active local invocation/controller cycle. Prefer the same current owner generation as the producer for the first bounded implementation. Any takeover requires separately validated current recovery-generation authority; do not automatically adopt a new owner. Do not enable publication, resubmit work, requeue the task, or claim noEffect.
2. Add a versioned host-generated cleanup receipt only after the original generation's cleanup RPC succeeds. Bind generation, process identity, thread and turn, method and confirmed completion. Carry it in execution metadata and persist it in RoleService. Recheck original generation/child identity after awaiting cleanup, as well as before issuing it. A bare cleanupSucceeded boolean from provider text or worker report is invalid. Missing, false, malformed, wrong-generation, failed or timed-out cleanup stays unknown.
3. Explicitly document receipt scope. It can attest that the trusted provider completed its managed terminal cleanup. It does not establish confinement, no writes, no external actions, or absence of arbitrary detached commands. If shutdown's processQuiescent contract includes such escaped activity, add independent supported quiescence evidence and refuse until available; an adapter alone cannot solve that requirement. Known live escaped processes or unresolved effects must block release even with the receipt.
4. Prepare a distinct terminal failure result from the existing durable execution, copying the exact snapshot identity checks rather than weakening #assertTerminalIdentity. Validate role, attempt/task/claim, fencing token, contract snapshot, provider/context/thread/turn, request/settings, lane and binding identities. Verify no publication/candidate intent was created and no writer integration remains unresolved. Preserve report/private bytes and record not_published explicitly; known potential cooperative writes are not a no-effect claim.
5. After every await, reread all provider/settings/owner/claim/output facts before committing. Host admission must remain fenced through preparation, store reconciliation and final release. Shared workspace drift must never be normalized into the original candidate or called not-written; either retain a measured diagnostic observation or refuse if it makes effects/publication unresolved. A later ordinary acceptance must still detect manifest mismatch.
6. Convert only validated eligible attempts into the existing unknown/settling recovery state, then use store.reconcileAttempt with a failed/canceled result and truthful quiescence evidence. Keep executor intent/thread reservation/dispatch-journal closure consistent. Persist a stable preparation/evidence digest and support retry after each crash boundary, including store terminal settlement preceding executor closure. Do not call reconcileAttempt twice blindly: its second call rejects attempt_not_unknown; use validated terminal replay and the existing terminal digest for idempotence. No success receipts or finalization should be generated.
