- `test/server-delivery-engine.test.js:486-575` starts the real `startServer` composition with a temporary Git project, fake auth metadata, local settings selecting `concurrent-v1`, fake App Server, and real `LeadOrchestrator`; `:582-632` exercises authenticated status/steer while provider calls are held. This is the best starting shell for the integrated release test. It is not a full objective lifecycle test.
- `test/concurrent-recovery-acceptance.test.js:62` and `:209-224` run the composed server with fake provider turns and a mandatory check; its scenario recovers a known worker failure and reaches accepted checks. It disables auto-resume and injects one provider identity (`:77-82`, `:209-212`), with no account failover or process reopen.
- `test/concurrent-delivery-engine.test.js:1017-1104` composes router and concurrent engine, persists objective/check identity and attempts, closes/reopens SQLite, changes router default to legacy, and resumes the mapped run on concurrent. - `test/server.test.js:1976-2040` is an actual two-profile server fixture: profiles A/B, fake `appServerFactory`, injected `readProfileLimits`, switch to B, and auto-resume. `test/budget-watcher.test.js:260-280` covers no-switch wait and immediate first-available-account selection independently. These exercise legacy budget pauses, not concurrent engine's objective budget lifecycle.

## Composition gaps and runtime constraints

- New server settings default to legacy (`src/server.js:1411-1418`); concurrent selection must be explicitly written in temporary project settings. The router pins each run's engine and routes later resume by mapping (`src/delivery-engine-router.js:113-129,149-168`), so changing default at restart does not migrate it. Server startup validates workspace identity, OAuth account type, locks, acceptance settings and concurrent isolation before engine startup (`src/server.js:1270-1275,1305-1370,1402-1423,1464-1496`). Reopen tests must close fully before reopening the same state/workspace; server lock checks reject overlapping ownership (`test/server.test.js:1065-1084`).
- Temporary projects and fake accounts can avoid production settings/credentials: `startServer` accepts temp `accountsDir`, fake `appServerFactory`, fake limits, token/state paths (`src/server.js:1243-1266,1277-1291`); `test/server.test.js:1934-1966` proves profile-selected homes and fake `getAccount()`. `:1976-2036` proves two homes plus fake provider limit responses. For concurrent fixtures, provide disposable `auth.json` account IDs or inject `providerIdentityPinFactory` as in `test/concurrent-recovery-acceptance.test.js:77,129-132`; this invokes no live provider. A production App Server/auth integration smoke is a separate explicitly scoped check.
- The server's `budgetWatcher` is wired to `listBudgetPausedRuns`, legacy task pause metadata, loopback A2A resume and the optional switching wrapper (`src/server.js:1530-1554,1670-1726`). Concurrent `DeliveryLifecycle` currently creates durable waits/wakes with injected `budgetWakeEligibility`/`onWake` (`src/delivery-lifecycle.js:37-63,99-133`), but engine lifecycle construction in startup/shutdown paths supplies no trusted account eligibility or wake adapter (`src/concurrent-delivery-engine.js:402-406,846-850`). Current status says new-engine startup inactive and CN-14/CN-15 remain unaccepted (`docs/architecture/concurrent-harness/implementation-status.md:336,375-388`). Do not claim a concurrent account-A/B wait/reopen/resume path from the legacy budget tests.

## Smallest credible AD-08 release test and ownership

Add one integrated test (suggest `test/autonomous-delivery-release.test.js`) starting through `startServer`/`DeliveryEngineRouter`, with isolated workspace, SQLite, storage, settings, profiles A/B and fake App Servers/limit responses. Use scripted provider responses to drive exhaustion at A then B, durable wait, host reopen, eligibility/reset, automatic same-objective resume, required check and accepted status; inspect mapping/objective/checkpoint/attempt/effect/event history. Parameterize or use adjacent runs for pause/cancel at automatic transition boundaries and non-accepted recovery cases. Reuse server fixture helpers/patterns, not real provider calls.

Disjoint prerequisites/ownership: AD-02/03 own account transfer, context and durable wait/wake/restart eligibility; AD-04 owns investigation/technical recovery and genuine owner-question distinction; AD-05 owns uncertain effect reconciliation and pause/cancel race arbitration; AD-06 owns final acceptance evidence and failed-check truth; AD-07 owns durable status/steering and owner control. AD-08 should own only the composition test, fixture adapter and release assertions, with dependencies implemented/reviewed first. It should not duplicate comparative/economy trials.
