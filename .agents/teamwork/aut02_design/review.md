2. `src/lead-graph.js:1250`, `src/lead-graph.js:2563`: `outcomeSummary` omits the full assignment and `verify` clears `batch`, while `continueLimited` retains templates only for a usage-limited candidate. Persist the smallest versioned recovery record before clearing the batch: `{v:1, checkpointId, sourceAttemptId, sourceAssignmentId, role, oldTargetIdentity, generation, phase, reviewerTemplate}`. Store it in graph checkpoint state, keyed by run and checkpoint (run is already in the checkpoint). The stored obligation owns the exact six-field review object; do not duplicate or derive scope from summaries. `reviewerTemplate` needs only validated role-specific permission/pin fields required for dispatch (not an old thread, continuation, target, outcome, or A-specific prose). Read-only auditor can use empty write scope. Bound record count and generations per checkpoint, including across restarts and A->B->C churn.

## Suggested bounded selection

On a supported stale signal, select the matching stored obligation. First recompute current graph target, require it known and changed from the captured origin, no pending same-checkpoint writer, and no unresolved writer. Choose verifier unless `currentGateState` already has a valid current verifier; choose auditor only when the review kind requires it and the verifier is current. A fresh verifier may change the target through authorized test-only writes; reevaluate on integration. Increment a per-checkpoint generation only when a new candidate target is selected. A failed fresh review, repeated stale signal at an unchanged target, exhausted generation cap, unknown origin/target, or missing template returns to bounded lead replanning or the existing pause path, without granting new rounds or budget.

Non-blocking: `src/lead-graph.js:1564` already includes the complete stored review object in lead prompts, so it is suitable as the safe legacy replan context. `src/review-policy.js:34` compares all six fields and `src/lead-graph.js:772` binds receipts to current target; retain these controls unchanged.

Pitfall: Do not equate a direct endpoint's target hash with the graph target hash, or treat an endpoint rejection as a receipt.
