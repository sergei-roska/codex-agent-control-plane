## Implemented host API

- `createDeliveryRoleCapabilities({ backlogStore, candidateReview, projectWorkspaceFor, scratchRootFor }).resolveVerifierCapability(claim, normalizedRequest)` reads authoritative objective/task/attempt/claim, rebinds through `CandidateReview.bindClaimedAttempt`, recomputes stable request digest from normalized request + durable settings/contract pins, prepares/verifies frozen candidate, rejects canonical path/symlink/overlap failures, and returns a frozen opaque module-branded token.
- `scopedExecutionDetails(token)` is host-only. It exposes candidate ID/path/manifest, scratch root, permission workspace, capability/request identity, `assertCurrent()`, `verifyCandidate()`, `pinObservedThread(threadId)`, and `settleReviewReceipt(outcome,evidenceRefs)`. Receipt settlement forwards to `CandidateReview.settleReceipt`; CandidateReview remains the authority.
- `TaskExecutor` accepts `resolveVerifierCapability` and optional `receiptAdapter({ task, attempt, contract, outcome, evidence, remote, duplicate, deliveryCapability })`. It normalizes before digesting, resolves independently, puts only claim lookup fields and opaque capability ID in A2A metadata, persists the actual A2A artifact thread ID, settles the BacklogStore attempt before receipt callback, and returns receipt state unknown if the callback fails.
- `registerRoleAgents` accepts the same resolver. It resolves independently before empty `allowedFiles` validation; scoped calls bypass only static workspace writer/lane admission, reserve by attempt, run in private scratch, and retain local reservation unless explicit no-send/rejected/terminal evidence exists.
- `CodexAppServer.run({ ..., deliveryCapability })` accepts a separate host-only token, rechecks durable claim/candidate/path, rejects continuation, sends `thread/start` with `sandbox: 'workspace-write'` and no `permissions`, and sends `turn/start` with explicit writableRoots limited to scratch, verifier IPC network access, both tmp exclusions, and inherited approvals. It verifies the candidate after run and pins the provider thread.
- At the `turn/start` `_request` synchronous `onSending` callback, scoped execution rechecks the durable claim/control and frozen candidate after `onTurnStart`, immediately before setting `turnStartSent` and calling `_write`. A recheck failure follows the existing write-error cleanup, reports `turnStartSent: false`, sends no turn, and leaves the normal run cleanup path to remove its reservation.
- `CodexAppServer.prepareThread({ role, cwd, permissionWorkspace, selectedSkills, selectedMcpTools, executionPermissions, sandboxPolicy, ephemeral })` creates/registers a physical provider thread without a model turn. It stores MCP pin digests in the same format as run and computes turn policy with the same profile/native-legacy/strict branches, including a read-only policy for a read-only lead under inherited full-access owner settings.
