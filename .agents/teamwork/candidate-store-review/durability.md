Read: `CandidateStore.putBlob` at `src/candidate-store.js:226-236` writes a temporary blob with `writeFileSync` and renames it without flushing either the file or the `blobs` directory. `storeManifest` at lines 263-281 then inserts the complete manifest JSON in SQLite. `commitCandidate` at lines 352-408 checks the blob through `readManifestUnsafe` and commits a `known` candidate. These reads prove current visibility and digest, not persistence after power loss. There is no `fsync`/`fdatasync` in the module. The manifest file is a reconstructible cache, but blob bytes are the sole immutable content; the SQLite manifest contains only their digests, sizes and paths.

Mechanism: after a blob rename becomes visible, SQLite may durably commit the snapshot and known candidate while the blob's data or directory entry remains only in the OS cache. A power loss can leave the durable rows and references intact but the blob missing or incomplete. `readManifestUnsafe` then fails, and neither the cache repair nor the later changed workspace can reconstruct the original bytes. The current tests use process/reopen/fault cases; they do not establish cross-filesystem write ordering. The handoff's statement that Git/filesystem effects are not atomic with SQLite does not cover this known-candidate content-retention obligation in the CN-04 brief and target design.

Recommended bounded repair: before the SQLite snapshot row can commit, flush each new blob's temporary file, rename it, then flush the `blobs` directory entry. Ensure referenced existing blobs also have a durable file and directory entry, and flush newly created storage directories or parents before depending on them. Keep the manifest cache reconstructible. Fail closed if a required flush fails. A focused fault-injection test should make each flush fail and assert no snapshot or known-candidate row commits; a call-order test should show blob data and directory durability barriers precede the SQLite manifest/known commit. A normal subprocess restart is useful but cannot prove power-loss durability.
