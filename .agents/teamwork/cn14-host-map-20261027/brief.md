## Safety and disposable fixture

- Provider death/effect ambiguity: prototype returns facade only after terminal wait; its prior real run failed before verifier with `prior_turn_reconciliation_required`/unknown planner effect and `safeToRelease:false` (core handoff). Treat unknown effect as held/fenced, never unlock or accept. `recoverStoredRuns` classifies unknown recovery and only starts eligible planning/executing objectives (`incomplete.js:195-210`).
- Lock/drain: server owns state and workspace locks in `startServer`; close currently cancels Lead executor, waits bounded drain, then closes provider/HTTP/state and releases locks (`server.js:1000-1034`). Concurrent engine shutdown must be awaited before state close and lock release; prototype fences controllers, awaits cycle/scheduler/role-call drain and throws unless each projection says `safeToRelease:true` (`incomplete.js:296-308`). Never treat timeout or provider death as safe release.
- Disposable fixture entrypoint: `test/server.test.js`/`test/server-startup.test.js` use `startServer({listen:false, workspace:<tmp>, appServer:<fake>, state:<test state>, projectSettingsFile:<tmp>})`; inspect exact named helpers before reuse. Launcher side has injectable `createProjectManager` spawn/fetch and `createLauncherApp` factories in `src/launcher-projects.js` and `src/launcher-app.js`, with dedicated `test/launcher-app.test.js` and `test/launcher-projects.test.js`. Prefer fake AppServer and temporary dirs/DB; no real provider, account, or project server.
