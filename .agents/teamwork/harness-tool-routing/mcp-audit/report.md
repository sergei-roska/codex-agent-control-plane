# Drupal MCP read-only audit

Source: `/home/sr/Projects/Workspace/mcp-forge` working tree inspected as-is on 2026-10-16. No tests or MCP servers were run. `drupal-browser` was excluded. Registration counts below come from each `bin/server.php`; handler summaries were checked against each `src/Tools/*.php` and README.

## Cross-package contracts

All six use stdio MCP SDK servers and lazy root discovery (`shared-args/src/LazyProjectRoots.php:29-94`, `ProjectRootResolver.php:14-111`): `PROJECT_ROOT`, `--project-root`, package install ancestry, CWD ancestry, then client `roots/list`; Drupal root uses `DRUPAL_ROOT`, `web`, `docroot`, else project root. Client roots are accepted when they resolve as Drupal projects. This is broad machine filesystem access to the selected project's code/config/database. No per-tool confirmation gate exists. `drupal-static` scans/parses local files only (FileAdapter excludes vendor, node_modules, core, .git, and sites/default/files); other packages reach live Drupal or DB.

All registered tools are read-oriented in current handlers; no tool issues application writes, and DB package SQL is SELECT-only. Read does not imply low sensitivity: output includes watchdog message/hostname/location, config data/overrides, state values, permissions, render arrays and environment metadata. Drush packages start external `lando`, `ddev`, local `vendor/bin/drush`, or global `drush` processes. Config/content/ops/render adapters execute generated PHP through Drush `php-eval` (eval inside Drupal; 30-second timeout); the snippets are package-authored and parameters generally passed separately. No outbound HTTP/network client calls found; Lando/DDEV/DB can of course communicate with configured services. No MCP-specific secret/token requirement found. Drush inherits process environment including DRUSH_OPTIONS_URI/DRUSH_URI. `drupal-db-ops` reads `sites/default/settings.php` by PHP include and obtains DB credentials, then opens PDO; settings.php is executable project code, not a passive config parser.

## Packages and tools

- **drupal-static - 12 tools; recommendation: suitable for task-scoped routing for source/code/config-sync analysis.** `bin/server.php:1-145` registers `list_custom_modules`, `find_hook_implementations`, `find_service_definitions`, `find_event_subscribers`, `find_plugin_classes`, `find_form_classes`, `find_controller_handlers`, `find_preprocess_functions`, `find_drush_commands`, `trace_runtime_to_code`, `summarize_code_inventory`, `read_sync_config`. They enumerate or filter local custom/contrib code symbols, route/service YAML, or sync YAML; tool arguments are symbols/module/theme/path/config filters, plus pagination/verbosity for sync config. FileAdapter methods read and parse files only (`src/Adapter/FileAdapter.php:28-93`). No writes, subprocesses, DB, network or credentials. Package dependencies: MCP SDK, shared-args, Symfony YAML/Finder, nikic/php-parser; PHP >=8.1.
- **drupal-config - 10 tools; recommendation: suitable for config-specific routing with live-read/data-sensitivity controls.** Registered in `bin/server.php:1-150`: `inspect_config_object`, `trace_config_dependencies`, `find_config_owner`, `analyze_config_impact`, `inspect_config_split_state`, `inspect_recipe_state`, `summarize_deployment_risk`, `debug_state_system`, `diff_active_vs_sync`, `detect_config_drift`. They read active config/state/splits/recipes through Drupal and sync YAML from disk; parameters select names, source, direction/depth, split/recipe, allowlisted state key/profile, prefix and shared pagination. Adapter uses Drush php-eval and passes arguments via JSON/base64 wrapper (`src/Adapter/DrushAdapter.php:44-126`). Read-only. Needs bootstrappable DB/Drush; PHP, SDK, shared-args, Symfony Process/YAML. No confirmation.
- **drupal-content - 16 tools; recommendation: suitable for content-model/schema tasks, task-scoped.** `bin/server.php` registers `inspect_content_types`, `inspect_media_types`, `inspect_taxonomy_models`, `inspect_field_usage`, `inspect_reference_graph`, `summarize_editorial_model`, `inspect_display_modes`, `inspect_revisioning`, `inspect_translation`, `inspect_moderation`, `inspect_entity_types`, `inspect_bundles`, `inspect_fields`, `inspect_menus`, `inspect_vocabularies`, `inspect_permissions`. All inspect live entity definitions/field metadata/workflows/menus/permissions using Drupal APIs; filters are entity/bundle/vocabulary IDs and shared query/pagination fields. `src/Adapter/DrushAdapter.php:14-131` selects Lando/DDEV/local Drush and runs eval. Read-only, no content mutation. Requires bootstrappable Drupal 10/11 + Drush; SDK/shared-args/Process/YAML.
- **drupal-ops - 14 tools; recommendation: route only for runtime diagnostics/registry tasks; elevated data sensitivity.** `bin/server.php` registers `debug_watchdog`, `debug_queue_state`, `debug_cron_state`, `debug_cache_state`, `debug_update_state`, `debug_environment_summary`, `debug_state_system`, `debug_runtime_health`, `debug_failed_operations`, `inspect_modules`, `inspect_services`, `inspect_plugins`, `inspect_routes`, `search_runtime_objects`. They inspect live logs, queue/cache/cron/update/state health and runtime registries, with corresponding filters/sample toggles and pagination. Adapter invokes Drush php-eval (`src/Adapter/DrushAdapter.php:43-124`). Read-only but watchdog/queue samples can disclose operational or user data. Requires bootstrappable site/DB and Drush; SDK/shared-args/Process/YAML.
- **drupal-render - 10 tools; recommendation: suitable for render/theme tasks, with care on live content output.** `bin/server.php` registers `inspect_theme_state`, `inspect_template_suggestions`, `trace_template_resolution`, `find_preprocess_chain`, `inspect_render_array`, `inspect_library_attachments`, `inspect_blocks_and_regions`, `inspect_sdc_components`, `summarize_render_path`, `inspect_themes`. They query active theme/template resolution, regions/blocks/SDCs and build node/block render arrays; parameters are hook, target type/id, view mode/depth, region/component. Render-array handler strips `#cache`/`#attached`; library tool separately returns attachments/settings keys. Adapter runs generated PHP by Drush eval (`src/Adapter/DrushAdapter.php:44-124`). Read-only, but render output may expose content. Requires bootstrappable Drupal 10/11 + Drush; SDK/shared-args/Process/YAML.
- **drupal-db-ops - 14 tools; recommendation: restricted routing only for explicitly authorized DB diagnostics/config inspection; highest credential/data boundary.** `bin/server.php` registers `debug_watchdog`, `debug_queue_state`, `debug_cron_state`, `debug_cache_state`, `debug_update_state`, `debug_environment_summary`, `debug_state_system`, `debug_runtime_health`, `debug_failed_operations`, `inspect_config_object`, `diff_active_vs_sync`, `detect_config_drift`, `analyze_config_impact`, `summarize_deployment_risk`. SQL tools SELECT from watchdog, queue, semaphore, cache, key_value, system, config tables; update-state may additionally scan update-hook files; config tools compare active SQL config with sync YAML. PDO uses fixed table identifiers with settings-derived prefix and prepared values (`src/Adapter/PdoAdapter.php:104-158`; tool SQL under `src/Tools`). No write SQL found. However adapter includes executable `sites/default/settings.php` (`PdoAdapter.php:59-84`) and connects using its credentials; requires filesystem access to settings and network/socket DB reachability. No user confirmation. PHP/SDK/shared-args/Symfony YAML/PDO driver.

## Dirty-source deltas

`git status --short` showed deletion of all `drupal-browser` files (excluded) and modified composer.json in all six packages, plus `drupal-config/src/Tools/TraceConfigDependencies.php`. Each composer change adds `options.symlink=false` to the local shared-args path repository; dependency declaration/runtime contract otherwise unchanged. The dirty TraceConfigDependencies change adds enum validation and passes requested `direction` into the generated PHP params, correcting handler use of direction; this materially affects trace results. Preserve these changes.
