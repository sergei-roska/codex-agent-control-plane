Implemented API: `new DeliveryRoleService({ db, backlogStore, candidateStore, candidateReview, outputArtifacts, lanes, roles, appServer, workspace, baseUrl, authMiddleware, authToken, settingsFor, roleFor, resolveVerifierCapability, checkEvidenceFor, selectedSkillsFor, selectedMcpToolsFor, executionPermissions, getProviderIdentity, clock, privateRoot })`. Methods: `register(app)` mounts auth-protected card and JSON-RPC at `/delivery/agents/<role>`; `transportFor({ role, settings, transportKey }, attemptId)` returns SDK transport methods `sendMessage`, `getTask`, `findByContext`, `cancel`; `resultAdapter({task,attempt,contract,objective,remote})`; `receiptAdapter({task,attempt,outcome,evidence,remote,duplicate,deliveryCapability})`; `producerEvidenceFor(binding)`; `authorizeArtifactBinding(binding)`; `getExecution(attemptId)`; `projection()`.

`checkEvidenceFor({ task, attempt, execution, candidate, requiredCheckPins })` returns exact attempt/fence/context/thread/candidate/input-manifest/settings/request pins, ordered `checkPins`, one `{checkId,state:'passed',evidenceRef}` result per pin, bounded `evidenceRefs`, and `evidenceDigest = sha256:${sha256(canonical(proofWithoutEvidenceDigest))}`. Empty pins are vacuous. Nonempty pins default deny. Verifier review also uses current `CandidateReview.getReviewTask`, known scoped read paths, `reviewResult`, frozen verifier capability, and `settleReviewReceipt`.

Product lane is captured and published only inside TaskExecutor's later `resultAdapter`, after submission has been acknowledged. The service never uses `integrate:true`. The execution registry is durable; reopened active rows project unknown and are not resent. Artifact bridge must attach CandidateStore via `candidateStoreOptions()` and use lazy callbacks into the service for `authorizeArtifactBinding` and `producerEvidenceFor`.

Publication refusal is grounded in current CandidateStore evidence. An existing refused intent requires matching attempt identity and a released/reconciled exact admission record. A generation conflict without an intent is classified as a known no-effect refusal only when no admission exists, CandidateStore has a newer known child of the exact base, the requested generation is stale, and the live workspace manifest equals that current candidate. A stale bridge-history-only `refused` row remains unresolved; it cannot settle the attempt.

Known failure before `AppServer.run` records `externalState=FAILED`, `terminalStatus=not_started`, and settled no-effect evidence. Once invocation may have begun, uncertainty is preserved absent actual terminal/rejection proof.

Root granted `src/codex-app-server.js` and `test/delivery-verifier-integration.test.js` for scoped verifier strict mode. Scoped execution now requires the requested permission setting to match the selected mode: inherit/inherit or strict/strict. Thus inherit resolving to `strict` because native policy is unavailable is denied. Strict mode uses the existing `on-request` / `user` approval settings; inherited settings remain unchanged.

Role cards and execution provenance preserve actual Fast modes `inherit`, `off`, and `on`; legacy boolean input is mapped to `on`/`off`. Terminal result handling now validates the captured attempt/task/fence/context/external-task identity and owner generation separately from fresh publication authorization. Same-owner pause/correction after an admitted turn settles as failed/no-publication, completes the private lane as `not_integrated`, releases claim capacity, and cannot produce a passed verifier receipt. Fence/owner-generation mismatch remains unresolved. All nonintegrating lane completion calls normalize the LaneStore `laneId` into the `LaneManager.complete` id shape so the lane really drains.
