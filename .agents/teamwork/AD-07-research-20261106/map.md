# AD-07 status and steering map

## Current contract and paths

- Concurrent owner steering is scoped through launcher `POST /api/projects/:id/delivery/steer`: validates exact body/scope and revision pins, fetches the control snapshot, forwards to host control, and validates receipt (`src/launcher-app.js:392-426`). Host `GET /control/delivery/:runId` and `POST .../steer` are authenticated and concurrent-only (`src/delivery-host-controls.js:43-61,87-118`). `ConcurrentDeliveryEngine.steer` creates/reuses the scoped inbox, checks plan/goal/control revisions, and wakes the controller (`src/concurrent-delivery-engine.js:546-581`).
- Receipt is durable, separate from application: inbox hashes message identity/body, returns `received`, exact replay returns duplicate prior state, changed body under same ID throws `message_id_conflict` (`src/delivery-inbox.js:50-83`). Planner completion marks included steering messages applied (`src/delivery-inbox.js:154-173`); controller applies owner corrections at cycle start (`src/project-delivery-controller.js:226-229`). Status exposes inbox/messages/pending plus objective and lifecycle (`src/project-delivery-controller.js:217-224`); engine control status exposes revisions, decisions, inbox and disposition (`src/concurrent-delivery-engine.js:652-669`).
- The rendered concurrent status is incomplete for AD-07: engine control status lacks explicit phase, next automatic action, selected account, provider wait details, blockers, checks, and final disposition/result. Existing backlog projection is task/capacity oriented, and its planner summary explicitly says objective attribution unavailable (`launcher-ui/backlog.js:96-104`).
- Concurrent engine has pause/resume/cancel primitives: pause and pause-cancel (`src/concurrent-delivery-engine.js:528-537`), lifecycle pause/cancel abort admitted work (`src/project-delivery-controller.js:160-199`). However concurrent host controls expose only GET/steer/decision routes (`src/delivery-host-controls.js:43-118`); launcher control API adds steer only (`src/launcher-app.js:392-426`). No matching end-to-end concurrent pause/cancel endpoint/UI is evidenced. Legacy pause routes remain distinct: `/control/pause` and `/control/pause/cancel`, pause parks at safe boundary without canceling workers (`src/server.js:1189-1223`); launcher legacy tests cover these (`test/launcher-pause.test.js:117-147`).
- Legacy chat/task path is separate: messages are saved as task messages and resumed through the orchestrator (`src/launcher-app.js:230-264`); executor distinguishes confirmed cancellation from requested-but-unconfirmed downstream A2A cancellation (`src/server.js:992-1017`). Legacy status is task state/pause metadata, not concurrent objective status.

## Tests and gaps

- `test/delivery-host-controls.test.js:70-100` covers scoped read/steering receipt and exact duplicate. `test/concurrent-delivery-engine.test.js:350-385` covers receipt then applied/blocked, replay idempotence, and changed-body rejection. `test/project-delivery-controller.test.js:104-137,180-196` covers receipt/application and restart persistence. These are deterministic tests, not browser acceptance.
- `test/launcher-backlog-ui.test.js:30-90` checks objective polling, stale selection, backlog rendering, but not status fields or pause/cancel. `launcher-ui/backlog.js:193-249` validates receipt and clearly labels `received` as not necessarily applied; polling then renders latest inbox state (`:141-160`). It does not show the full status fields listed above.
- Pause/cancel versus automatic budget resume race is not covered by these chat/control tests. Existing lifecycle tests cover pause pinning an earlier budget wake (`test/delivery-lifecycle.test.js:70-96`), while engine tests cover resume/coalescing and pause boundaries (`test/concurrent-delivery-engine.test.js:1410-1530`); no integrated race asserts a stale quota wake cannot override a concurrent owner pause/cancel. Add at the engine/lifecycle integration seam.
- LL-7 is recorded implemented but explicitly has open browser check (`docs/orchestrator-improvement-backlog.md:209`). Existing decision card code renders reason/question, evidence, recommended option, independent work and option controls (`launcher-ui/app.js:1263-1316`); current `test/launcher-decision-ui.test.js` checks submission, stale scopes, draft retention and option behavior, but not the full LL-7 browser acceptance content against an integrated rendered card.

## Smallest ownership-disjoint implementation slices

1. Backend owner: extend concurrent status projection/controller contract with phase, next action, provider/account and wait, blockers/checks, terminal result/disposition; retain legacy task status contract.
2. Control/API owner: add scoped authenticated concurrent pause/cancel host routes and launcher proxy routes, with revision/generation conflict semantics; leave legacy `/control/pause` flow intact.
3. UI owner: render the expanded status and concurrent pause/cancel controls in launcher backlog; preserve received-versus-applied language and retry ID/body behavior.
4. Acceptance owner: add deterministic pause/cancel versus budget wake race coverage, and browser acceptance for one LL-7 decision card showing reason, recommendation, evidence, independent work and option-only choice.
